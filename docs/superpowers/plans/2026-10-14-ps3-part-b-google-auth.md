# PS3 Part B Google Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Replace shared Basic Auth with Google sign-in, secure server sessions, and owner-enforced shared versus personal recipe collections.

**Architecture:** The existing Render Node service becomes a same-origin full-stack service serving React and /api. Google Identity Services supplies an ID credential once; the backend verifies it, stores users and hashed seven-day sessions in Neon, and issues a secure HTTP-only cookie. PostgreSQL queries and Express routes enforce recipe authorization from the authenticated session user.

**Tech Stack:** React 19, React Router, Express 5, PostgreSQL 17/Neon, google-auth-library, Node crypto, Vitest, Testing Library, Supertest, Vite, Render Blueprint

**Spec:** docs/superpowers/specs/2026-10-14-ps3-part-b-google-auth-design.md

## Global Constraints

- Production frontend and API share the existing Render Node service origin.
- Cookies are Secure, HttpOnly, SameSite=Lax, Path=/, and expire after seven days.
- Store only SHA-256 hashes of 32-byte random session tokens.
- OWNER_EMAIL determines owner status from a normalized verified Google email.
- Existing recipes migrate without data loss; null owner_user_id means shared.
- Normal users mutate only their personal recipes; only the owner mutates shared recipes.
- Requests never accept a user ID or role from the browser.
- Logs contain method, path, status, and timing only.
- Paid AI generation remains disabled.
- Keep the Part A static site until production verification completes.

- [ ] **Step 5: Implement tokens and cookies**

    import { createHash, randomBytes } from "node:crypto";

    export const SESSION_COOKIE = "cooking_saver_session";
    export const SESSION_MAX_AGE_SECONDS = 7 * 24 * 60 * 60;

    export function hashSessionToken(token) {
      return createHash("sha256").update(token).digest("hex");
    }

    export function newSessionToken() {
      return randomBytes(32).toString("base64url");
    }

    export function serializeSessionCookie(token, {
      secure = true,
      maxAge = SESSION_MAX_AGE_SECONDS
    } = {}) {
      return [
        `${SESSION_COOKIE}=${encodeURIComponent(token)}`,
        `Max-Age=${maxAge}`,
        "Path=/",
        "HttpOnly",
        ...(secure ? ["Secure"] : []),
        "SameSite=Lax"
      ].join("; ");
    }

Parse only cooking_saver_session. Middleware hashes it, loads an active session, attaches a role derived from normalized OWNER_EMAIL, or returns 401.
